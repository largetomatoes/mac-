## 下载与安装

3.14 提供 Mac、Windows 和同证书签名的 Android 安装包。变更、升级顺序及验证范围见 [3.14（320）发布说明](RELEASE_NOTES_3.14_320.md)；可下载文件以 [GitHub Releases](https://github.com/largetomatoes/wenjian-software/releases) 的实际附件为准。

从仓库的 **Releases** 下载对应系统的安装包。Mac（Apple 芯片）使用 `Wenjian-*-macOS-arm64.zip`，解压后把“问间”拖入“应用程序”；Windows x64 使用 `Wenjian-*-Windows-x64.zip`，解压后运行 `Wenjian.exe`。Android 8.0+ 使用 `Wenjian-*-Android.apk`，移动版以阅读和笔记为主；PDF 需要 WebView 111+。当前构建没有 Apple 公证或 Windows 商业代码签名，系统首次启动时可能要求手动允许。

应用本身不需要登录。未配置云备份时，笔记和电子书只保存在本机；已有的独立“问间同步”目录仍保存笔记，不会改动 Obsidian 的目录。问间会核对并复制旧目录中的原书到应用自己的本地书库，之后导入的新书也保存在此处。启用三端同步后，书籍原件会另行上传到所选的云端资料库；旧目录中的原书暂时保留，方便回退。若原数据目录暂时不可用，应用会停止启动，避免误建空白资料库。

## 首次使用与核心问题

问间 2.0 首次打开时填写自己的核心问题，或选择“导入已有备份”恢复自己的完整资料，之后进入只有一个根问题的空白关系图。原有用户升级直接使用原资料。点击底部问题页的「⋯」→「名称与页面设置」，可以修改当前问题的表述；根节点标识与已有内容不变，前后表述会保存在修改记录中。

全新用户需要在“书库 → Zotero”中选择连接后才会读取本机 Zotero；已经连接的旧用户保留联动。

## 日常使用与备份

- 问题树、回答、交叉思考、卡片集和修改记录保留思考的来源与形成过程。
- 全局搜索能按记得的大意寻找思考、回应、读书笔记、书籍思考和文稿，并打开对应记录。
- 未正式保存的卡片、问题页、读书笔记和文稿草稿会保存在本机；文稿修改时会检查版本冲突。
- PDF 和 EPUB 阅读支持原文摘录、过程笔记、读书笔记和书籍思考。保存后的过程笔记可增减问题与交叉板块关联；附近批注自动分组，悬停预览、点击分别查看，从问题页可回到原文。
- PDF 优先使用原生文字；需要 OCR 的页面自动在本机识别，缓存按识别版本和页面旋转区分。新摘录合并 PDF 排版产生的行内换行，按笔记窗口宽度自然折行，保留可识别的段落、英文词间空格和列表；保存前可校对，并选择“保留原文分行”。原始摘录和页码位置保留，已保存的笔记不会自动重写。
- 书库左侧可新建文件夹分类、改名、移动书籍和按书名或作者搜索。选中文件夹后导入的新书自动归入其中；移除文件夹会把书放回“未分类”。分类仅整理书目，原文件、阅读位置和笔记仍保留。
- 在桌面应用的“问间”（Windows 为“文件”）菜单中选择“导出完整备份…”，可生成包含笔记、草稿和所有原书文件的 `.wenjian-backup`。备份会逐项校验，恢复时保留现有书籍文件，并在覆盖笔记前保留备用副本。旧版 JSON 备份仍可导入，但不包含原书文件。

## Zotero 本机联动

桌面版会从正在运行的本机 Zotero 10 读取个人资料库。Zotero 的“设置 → 高级”需开启“允许此计算机上的其他应用程序与 Zotero 通讯”；不需要账户密钥、插件或逐本添加。

点击“书库”先选择“读书”或“Zotero”。本地书籍按自己的文件夹整理；Zotero 文献与已下载到本机的 PDF/EPUB 按 Zotero 分类显示。问间在启动、回到前台及前台使用期间约每分钟检查更新；书库左上角也可手动刷新。书内“笔记”可查看 Zotero 摘录和批注，并引用原文写自己的思考、手动关联问题；搜索能找到这些摘录。没有本机附件时先保存文献记录，文件在 Zotero 下载后再自动补入。

联动方向是 Zotero → 问间，自己的思考不会写回或被来源批注覆盖。已复制原文和摘录离线可用，并随问间完整备份保存；同一条来源重复更新不会重复建书。从问间删除的文献不会自动再次出现，也不会删除 Zotero 原件。Zotero 中删除的材料保留已导入的本地记录；有意替换的原文件暂保留旧版，避免旧笔记的页码错位。当前不读取 Zotero 群组库。

## Mac / Windows / Android 三端同步

桌面左上角小点 →「同步与连接」；安卓右上角「同步」。坚果云使用邮箱和第三方应用密码，固定目录为 `问间资料库/sync-v1`，与 Obsidian 分开。OSS 使用独立的 `prefix/sync-v1`，完整备份仍保留在 `prefix/snapshots`。一次只启用一种服务。

3.00 支持先选择可信的设备书库，再继续多端合并：

1. 先为每台设备导出完整备份，并将参与同步的 Mac、Windows、Android 都升级到 3.00。
2. 在资料正确的那台设备打开同步窗口，选择“以这台设备的书库为准…”。核对与云端相比新增、替换和移除的资料数量，输入“以本机为准”，再“备份并发布本机基准”。Mac、Windows 或 Android 都可以作为这次基准。
3. 其他设备连接同一云端资料库并同步。已有设备会采用新基准；新设备可选择“以云端现有资料为准”。需要保留两套初始资料时，也可核对后选择合并。
4. 此后任意设备新增书籍、笔记或进度都参与合并。同一记录的并发修改保留冲突供选择；旧设备上未修改的过时记录不会因重新联网而恢复，未上传的独有改动会保留或提示冲突。

“资料库版本与恢复…”显示切换前保留的云端版本。恢复会备份当前资料，并把选定版本发布为新的共享基准。这些版本记录发生在手动切换基准时，不是每次保存都生成整库副本。

同步包括问题、笔记、批注、分类、阅读进度及书籍原件。同步到书目后，会主动下载本机缺失的 PDF / EPUB 原件并校验；传输失败会显示具体状态，可重试。书籍按内容 SHA-256 去重，完整原件已经存在时不重复下载。离线变更先留在本机，未提交的输入草稿仅保存在本机。

应用在前台定期检查：OSS 每分钟、坚果云每五分钟，也可立即同步。资料和文件状态均未改变时，只读取云端状态，不重复写入同步租约、笔记库或书籍检查时间；失败后逐步延长重试间隔，凭据错误时暂停自动尝试。坚果云单本书需小于 500 MB。旧坚果云同步目录会先复制核验，再切换到独立本地目录；原目录保留。

“整理云端旧历史”仍需手动发起：先完整备份、上传并验证新快照，再清理旧笔记批次。书籍原文件和用于版本恢复的快照保留，普通同步不会自动删除它们。云端占用也可能来自实际书籍、OCR 缓存、备份及保留的版本；3.00 减少无变化时的重复写入，不自动删除未知文件。

选择 3.00 的设备基准后，旧版客户端会暂停对该资料库的同步。请先升级所有设备；旧版更新提示可能无法识别 `v3.00` 标签，可直接从 Releases 下载。当前实现与验证边界见 [3.00 发布说明](RELEASE_NOTES_3.00.md) 和 [移动版说明](mobile/README.md)。

## 阿里云 OSS 云备份

问间可以把完整备份作为**私有、独立的快照**上传到阿里云 OSS。此入口用于手动完整备份与跨电脑迁移；2.1 另提供下述三端增量同步与 Android 阅读客户端。在一台电脑上传后，另一台 Mac 或 Windows 电脑可以配置同一个 Bucket，查看并恢复云端快照；恢复前应用会自动给该电脑的现有资料生成一份完整备份。上传前会检查云端是否出现其他设备的新快照，避免静默覆盖。

点击左上角“问间”旁的小褐色点，选择“云端备份”，再点“上传完整备份”。备份包含已导入的 PDF/EPUB 原文件、书籍分类、阅读进度、过程注解、读书笔记、高亮、OCR 缓存和草稿；云端保存为整份归档，恢复后在问间书库中阅读。仅在电脑或其他网盘里、尚未导入问间的书不会自动上传。

先在阿里云建立私有 Bucket 和专用 RAM 用户，将权限限定到问间使用的 Bucket/目录，至少包括 `oss:PutObject`、`oss:GetObject` 和 `oss:ListObjects`。不要使用主账号 AccessKey。然后在桌面应用菜单中打开“阿里云 OSS 备份…”，填写地域（例如 `cn-shanghai`）、Bucket、目录、RAM AccessKey ID 和 Secret。Secret 只在本机通过系统安全存储加密保存，不会写入 GitHub 仓库或备份文件。上传与下载使用 HTTPS 和 SHA-256 校验。OSS 存储、流量费用由你的阿里云账号承担。

云端快照包含笔记原文和书籍内容。请保持 Bucket 私有，妥善保管 RAM 密钥。阿里云的 [RAM 最小权限说明](https://help.aliyun.com/en/oss/user-guide/ram-policy/) 和 [AccessKey 安全建议](https://help.aliyun.com/en/oss/user-guide/reduce-the-risks-of-unauthorized-access-caused-by-accesskey-pair-leaks) 可用于设置权限。

## 开发

需要 Node.js 22 或更新版本。

```bash
npm ci
npm run build
npm run lint
node --test tests/test-complete-backup.cjs tests/test-oss-cloud.cjs tests/test-search-ranking.mjs tests/test-pdf-export.cjs
node tests/test-desktop-comparison.mjs
node scripts/test-cross-blocks.mjs
node scripts/test-graph-projection.mjs
npm ci --prefix work/mac-app
npm run package:mac --prefix work/mac-app # 在 Apple 芯片 Mac 上
```
